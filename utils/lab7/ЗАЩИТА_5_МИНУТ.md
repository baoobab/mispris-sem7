Проверка неверного сочетания:

```json
{ "values": { "diameter": 35, "cheese_g": 100, "topping": 18 } }
```

Создание допустимого исполнения (обозначение должно быть новым):

```json
{
	"number": "PZ-KALIK-30",
	"name": "Кальян-пицца 30 см",
	"values": { "diameter": 30, "cheese_g": 130, "topping": 18 }
}
```

Попытка добавить шаблон:

```json
{ "number": 3, "item_id": 22, "quantity": 1 }
```

После согласования для проверки блокировки выполнить PUT `/orders/1/positions/1` с телом `{"number":1,"item_id":24,"quantity":3}` — ожидается 409.

## Короткие ответы

- **Зачем вариант отдельным изделием?** Он имеет конкретные значения и может использовать существующие единицы, маршруты и позиции заказа.
- **Почему не записываем все комбинации заранее?** Вариант создаётся по запросу, после проверки ограничений.
- **Какой паттерн?** Интерпретатор: дерево выражений и рекурсивное вычисление в контексте параметров.
  Функции, классы функций, операторы, формальные аргументы, константы, вызовы, фактические аргументы и корни ограничений хранятся в связанных таблицах миграции 005. JSON используется для передачи запросов; поля definition/expression с хранимыми деревьями удалены. Интерпретатор читает нормализованные записи.
- **Что при ошибке?** Запрос откатывается; недопустимый вариант не попадает в справочник.
- **Почему отдельный маршрут у варианта?** Размер и состав влияют на ресурсы и труд; стоимость базы нельзя автоматически считать стоимостью варианта.

После показа снова выполнить `scripts/lab7_demo.py` — восстановится исходный черновик ORDER-007.
