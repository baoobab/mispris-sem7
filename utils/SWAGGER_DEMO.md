# Демо процедур задания №6 в Swagger

Сценарий для сервиса доставки готовой еды. В базе загружены данные сидера, приложение запущено, Swagger открыт. Во всех расчётах показываем партию из **10 пицц «Маргарита 30 см»**.

## Подготовить ID изделия

1. Выполни `GET /api/items/` с параметрами по умолчанию.
2. Найди строку с `number: "PZ-001"` и запомни её `id` как **ID пиццы**. `PZ-001-01` — острая модификация с другими нормами.

## 1. FIND_TM — весь технологический маршрут

1. Выполни `GET /api/items/{item_id}/technology/route`. В `item_id` подставь **ID пиццы**.
2. В ответе `200` операции идут в порядке зависимостей. Закупки предшествуют операциям, которые расходуют их ресурсы, замес и варка соуса предшествуют выпечке, упаковка идёт последней. `output_operation_id` указывает на «Пицца после упаковки» (`number = 20`, `depth = 0`). `depth` показывает расстояние до выходной операции по кратчайшей цепочке связей.
3. В `operations` найди «Пицца после выпечки» с тем же `item_id`, `number = 10` и `depth = 1`. Скопируй **поле `id` этой строки** для MR_Q. Номер шага `10` обозначает порядок в маршруте, а в `operation_id` передаётся ID строки.
4. В Swagger прокрути тело ответа до массива **`inputs`**. Покажи преподавателю строки с `out_operation_id` выпечки. Их `in_operation_id` указывают, в частности, на замес теста и варку соуса. Чтобы прочитать название любого шага, найди соответствующий `id` в массиве `operations`.
5. Покажи также, что упаковка использует выпеченную пиццу и коробку, а замес использует закупленную муку. Ниже ID из проверенного ответа для `item_id = 18`. Если ID в твоей базе отличаются, сопоставь их по `operations`.

| `out_operation_id` — операция, которая расходует вход | `in_operation_id` — что ей нужно |
|---|---|
| `18` — выпечка | `15` — тесто после замеса |
| `18` — выпечка | `16` — соус после варки |
| `19` — упаковка | `18` — пицца после выпечки |
| `19` — упаковка | `13` — закупленная коробка |
| `15` — замес теста | `1` — закупленная мука |

Всего в ответе сидера 13 позиций, 14 связей и максимальная глубина 3.

## 2. MR_Q — расход ресурсов на одну операцию

1. Выполни `GET /api/items/{item_id}/technology/operations/{operation_id}/materials`.
2. Укажи `item_id` = **ID пиццы**, `operation_id` = **ID выпечки из FIND_TM**, `quantity` = `10`. `quantity` здесь означает выпуск десяти пицц из операции выпечки.
3. В ответе `200` проверь четыре прямых входа. Покажи преподавателю `item_name`, `quantity` и `unit_symbol`. Поле `in_operation_id` связывает строку с операцией из FIND_TM.

| Вход выпечки | `quantity` | Базовая ЕИ |
|---|---:|---|
| Тесто для пиццы (`SF-001`) | 2.5 | кг |
| Соус томатный (`SF-002`) | 0.8 | кг |
| Моцарелла (`RM-010`) | 1.3 | кг |
| Базилик свежий (`RM-030`) | 0.05 | кг |

Покажи пересчёт моцареллы. Норма на одну пиццу задана в граммах, поэтому 130 г × 10 дают 1.3 кг в ответе.

## 3. SUM_MR — сводная потребность в закупке

1. Выполни `GET /api/items/{item_id}/technology/materials` с **ID пиццы** и `quantity = 10`.
2. В ответе `200` покажи `item_name`, `quantity` и `unit_symbol`. Количества уже приведены к базовым единицам.

| Закупаемая позиция | `quantity` | Базовая ЕИ |
|---|---:|---|
| Мука пшеничная в/с (`RM-001`) | 1.5 | кг |
| Вода питьевая (`RM-002`) | 0.9 | л |
| Дрожжи сухие (`RM-003`) | 0.025 | кг |
| Масло оливковое (`RM-004`) | 0.05 | л |
| Соль (`RM-005`) | 0.0455 | кг |
| Моцарелла (`RM-010`) | 1.3 | кг |
| Томаты (`RM-020`) | 0.96 | кг |
| Базилик свежий (`RM-030`) | 0.058 | кг |
| Коробка для пиццы 30 см (`PK-001`) | 10 | шт. |

3. Покажи разницу с MR_Q. Тесто и соус раскрылись до закупаемых ингредиентов, коробки пришли из упаковки. В строке базилика сложились 0.05 кг из выпечки и 0.008 кг из соуса.

## 4. TR_TO — трудоёмкость партии

1. Выполни `GET /api/items/{item_id}/technology/labor` с **ID пиццы** и `quantity = 10`.
2. В ответе `200` покажи две строки по `profession_name`. Повар замешивает тесто, варит соус и печёт пиццу. Упаковщик укладывает её в коробку. В демо у обеих профессий задан 3-й разряд. Его можно сверить по `qualification_id` через `GET /api/enums/values/{value_id}`.

| `profession_name` | `setup_minutes` | `piece_minutes` | `total_minutes` |
|---|---:|---:|---:|
| Повар | 11 | 98 | 109 |
| Упаковщик | 0 | 10 | 10 |

У повара подготовка занимает 5 минут на выпечку, 3 на замес и 3 на варку. Штучное время складывается из 70 минут на выпечку, 20 на замес и 8 на соус. Упаковщик тратит по 1 минуте на пиццу. Суммарная трудоёмкость партии по двум строкам — 119 минут.

3. Повтори запрос с `quantity = 1`. У повара останется 11 минут подготовки, а `total_minutes` станет 20.8. У упаковщика `total_minutes` станет 1. Так видно, что подготовительное время учитывается один раз на операцию за партию.
