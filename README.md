# Сервис доставки готовой еды — справочники, ХО, BOM и маршрутная технология

REST API на FastAPI + PostgreSQL. Дисциплина «Методы и средства проектирования информационных систем», семестр 7.

| Задание | Что реализовано |
|---|---|
| №1–3 | Классификатор изделий, перечисления, параметры, справочник изделий, единицы измерения |
| №4 | Хозяйственные операции: классификатор ХО, шаблоны (параметры, роли), экземпляры ХО, документы, позиции |
| **№5** | **Материальная спецификация (BOM)**: типы изделий, состав с нормами расхода, версии и история изменений, модификации базовых изделий, состав на всю глубину (FIND_BOM), сводные нормы расхода по классу материалов (CALC_BOM) |
| **№6** | **Маршрутная технология**: состояния изделий, технологические операции, ГРЦ, инструмент и оснастка, профессии и квалификации, типовые процессы, сводные нормы и себестоимость |

## Архитектура

```
Router (HTTP) → Service (бизнес-правила) → Repository (ORM) → PostgreSQL (таблицы)
```

| Слой | Ответственность |
|---|---|
| `src/routers/` | HTTP: маршруты, валидация входа/выхода (Pydantic) |
| `src/services/` | Бизнес-логика и расчёты (`BomCalculator`); выбрасывает доменные исключения `src/core/errors.py` |
| `src/repository/` | Запросы к БД через ORM; только `flush()`, без `commit()` |
| `src/models/` | Таблицы SQLModel |
| `src/schemas/` | Схемы запросов и ответов |
| `alembic/versions/` | Миграции: `001` — схема №1–4, `002` — BOM (№5), `003` — маршрутная технология и расчётные функции (№6) |

- **Транзакция на запрос.** `get_session()` делает commit при успехе и rollback при ошибке, поэтому составные операции (например, правка состава + запись истории) атомарны.
- **Ошибки.** Доменные исключения переводятся в HTTP-коды: `NotFoundError` → 404, `BusinessRuleError` → 400, `ConflictError` → 409. Нарушение ограничений БД (`IntegrityError`) → 409. Ошибки валидации входа → 422.

## Задание №5: модель и процедуры

Таблицы: `item` (+ `item_type_id`, `base_item_id`), `item_bom` — позиция спецификации, `item_change` — история изменений.

| Процедура задания | Реализация | API |
|---|---|---|
| `FIND_BOM(pIdProd)` | `BomCalculator.find_bom(item, at)` (обход в глубину) | `GET /api/items/{id}/bom/tree` |
| `CALC_BOM(pIdProd, pQ)` | `BomCalculator.calc_bom(item, qty, class, at)` | `GET /api/items/{id}/bom/norms?quantity=&class_id=` |
| `CREATE_MODIFICATION(pIdBase, pName)` | `BomService.create_modification` | `POST /api/items/{id}/modifications` |
| `REGISTER_CHANGE(pIdProd, pChangeDesc)` | `BomService._register_change` (вызывается каждой правкой) | `GET /api/items/{id}/bom/changes` |
| — | действующая спецификация на дату: `BomCalculator.effective(item, at)` | `GET /api/items/{id}/bom?at=` |
| — | добавить / изменить норму / заменить / удалить компонент | `POST /bom`, `PUT /bom/{comp}`, `POST /bom/{comp}/replace`, `DELETE /bom/{comp}` |

Правила:
- у **материала** не может быть состава; изделие не может входить в собственный состав; **циклы** в составе запрещены (в том числе через модификации);
- ЕИ нормы расхода должна принадлежать компоненту (по умолчанию берётся его базовая ЕИ), нормы пересчитываются в базовую ЕИ через коэффициент;
- правка не перезаписывает строку: старая версия закрывается (`valid_to`), создаётся новая, а в `item_change` записываются ссылки «было → стало». Состав можно посмотреть на любую прошлую дату (`?at=`);
- **модификация** (`base_item_id`) наследует строки базовой спецификации с флагом базы `is_base` и хранит только отличия: переопределённые нормы, добавленные компоненты и строки-исключения (`is_excluded`) для удалённых. Изменения базового изделия сразу видны в модификациях. Строка с `is_base = false` действует только у самого изделия (например, упаковка);
- `CALC_BOM` без класса суммирует материалы (листья дерева). С классом суммирует компоненты класса и его подклассов, на каждом пути берётся первый компонент класса, без двойного счёта.

## Задание №6: маршрутная технология

Позиция маршрута — это состояние изделия после операции. Производственная позиция указывает класс операции,
групповой рабочий центр (ГРЦ), профессию, квалификацию, подготовительное время на партию и время на единицу.
Закупочная позиция обозначает материал или комплектующее, получаемое извне. Её входные ресурсы и трудоёмкость
пусты. ГРЦ связан с подразделением из справочника СХД; оборудование, инструмент и оснастка задаются моделями
и учитываются по инвентарным номерам. Квалификации хранятся в перечислении `qualification`.

Вход операции ссылается на конкретное состояние того же или другого изделия. Выходная позиция изделия
служит началом расчёта. Номер однозначно определяет порядок операций внутри изделия: вход того же изделия
может ссылаться только на предыдущую позицию. Циклы между изделиями запрещены. Для каждой позиции нужна
базовая единица количества изделия. `quantity` входа задаётся в единице входного ресурса,
`for_quantity` — в базовой единице результата операции.

| Действие | API |
|---|---|
| Классы операций, профессий и ГРЦ | `/api/technology/classes` |
| Рабочие центры, модели средств труда, инвентарь | `/api/technology/work-centers`, `/asset-models`, `/assets` |
| Операции, входы и требования к средствам труда | `/api/items/{id}/technology/operations`, `/operations/{op}/inputs/{in}`, `/operations/{op}/tools/{model}` |
| Импорт действующей BOM в операцию | `POST /api/items/{id}/technology/operations/{op}/import-bom?at=` |
| `FIND_TM(item)`: граф на всю глубину | `GET /api/items/{id}/technology/route` |
| `MR_Q(operation, quantity)`: расход прямых входов | `GET /api/items/{id}/technology/operations/{op}/materials?quantity=` |
| `SUM_MR(item, quantity)`: суммарный расход закупных ресурсов | `GET /api/items/{id}/technology/materials?quantity=` |
| `TR_TO(item, quantity)`: трудоёмкость по профессиям и квалификациям | `GET /api/items/{id}/technology/labor?quantity=` |
| Часовая ставка по профессии и квалификации | `PUT /api/technology/labor-rates/{profession}/{qualification}` |
| Себестоимость материалов и труда | `GET /api/items/{id}/technology/cost?quantity=&pricelist_set_id=` |
| Типовые процессы и применение к изделию | `/api/technology/templates`, `POST /api/items/{id}/technology/templates/{template}/apply` |

Импорт BOM использует нормы с учётом даты и модификаций и связывает компоненты с их текущими выходными
позициями. Он добавляет или обновляет соответствующие входы операции. Последующие правки BOM можно
перенести повторным импортом; лишние входы технолог проверяет и удаляет отдельно.

Расчётные функции PostgreSQL работают с `numeric`. Расходы по всем путям графа складываются и возвращаются
в базовых единицах. Подготовительное время прибавляется один раз на производственную позицию в партии,
а штучное умножается на суммарную потребность в её результате. Себестоимость использует цены за базовую
единицу из выбранного прейскуранта и часовые ставки. Суммы округляются до копеек по строкам; если цена
или ставка отсутствует, API возвращает 409 с перечнем недостающих данных.

Типовой процесс хранит общие шаги и связи. Для изделия отдельно передаются значения параметров и привязки
внешних ресурсов. Формулы расхода и времени имеют вид `constant + сумма(factors[параметр] × значение)`.
При применении шаблона к изделию без операций сервер проверяет формулы и создаёт редактируемый маршрут
одной транзакцией. Исходный шаблон и использованные параметры остаются доступны через API.

## Запуск

Проект поддерживает Python 3.11–3.14. Для существующей БД достаточно выполнить
`alembic upgrade head`; заполнение демо-данными для обновления схемы не требуется.

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env                 # при необходимости поправить логин/пароль PostgreSQL
psql -h localhost -U postgres -c "CREATE DATABASE mispis_sem7;"
alembic upgrade head
python data/seed.py                  # демо-данные «доставка еды» (очищает БД!)
uvicorn src.main:app --reload        # http://localhost:8000/docs
```

## Демонстрация (после `python data/seed.py`)

1. `GET /api/items/` — найти «Комбо «Обед на двоих»» (CB-001), «Пицца Маргарита 30 см» (PZ-001) и модификацию PZ-001-01.
2. `GET /api/items/{CB-001}/bom/tree` — состав набора на всю глубину с нормами на 1 набор.
3. `GET /api/items/{CB-001}/bom/norms?quantity=10` — закупка сырья на 10 наборов; `&class_id={Сыры}` — только сыры.
4. `GET /api/items/{PZ-001-01}/bom` — модификация: унаследованные и собственные строки.
5. `PUT /api/items/{PZ-001}/bom/{Моцарелла}` `{"quantity": 140, "reason": "..."}` → `GET .../bom/changes` — история «было → стало»; `GET .../bom?at=<время до правки>` — старый состав.
6. Ошибки: добавить пиццу в состав теста (цикл → 400), состав у материала (400), повторный компонент (409).
7. Для `CB-001` откройте `GET /api/items/{id}/technology/route`: в графе будут комплектация, упаковка и
   выпечка пиццы, подготовка полуфабрикатов и закупки. `/technology/materials?quantity=10` и
   `/technology/labor?quantity=10` покажут ресурсы на 10 наборов.
8. Возьмите ID прейскуранта из `GET /api/positions/pricelist-sets` и передайте его в `/technology/cost`.
   У `PZ-001` и `PZ-001-01` сравните `/technology/template-application`: шаблон общий, значения разные.
